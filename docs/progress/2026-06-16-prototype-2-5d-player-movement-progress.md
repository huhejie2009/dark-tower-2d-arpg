# 2026-06-16 2.5D 原型玩家移动与镜头进度

## 背景

上一轮已把进塔后的 2.5D 原型从黑屏/空场景修到可见灰盒房间。本轮继续推进推荐路线：先让玩家在新模式里可控，并建立相机阅读性基线，避免后续敌人追击、碰撞、清怪流程建立在不可玩的场景上。

## 本轮完成

- 2.5D 原型场景接入玩家移动输入：
  - 使用现有 `move_left` / `move_right` / `move_forward` / `move_back` 输入动作。
  - 输入映射到 3D XZ 平面，W/上方向为画面上方，S/下方向为画面下方。
  - 原型内玩家移动速度从旧 2D 像素尺度调整为 3D 房间尺度，避免一按键就穿越房间。
- 2.5D 原型相机加入正交跟随：
  - 保持固定俯角和固定偏移。
  - 玩家移动时相机跟随 XZ 平面位置，保证玩家始终在可读构图内。
- 增加测试专用接口：
  - `set_player_move_input_for_test(value)`
  - `clear_player_move_input_override_for_test()`
  - `build_player_control_snapshot_for_test()`
- 增加回归测试：
  - `tests/regression/regression_prototype_2_5d_player_movement_contract.gd`

## 验收标准

- 原型场景加载后必须暴露玩家控制快照。
- 玩家必须可被输入驱动。
- 玩家移动必须限制在 XZ 平面，不产生 Y 轴漂移。
- 右方向输入必须让玩家沿 +X 移动，并更新朝向为 `right`。
- 正交相机必须保持当前相机状态，并随玩家沿 X 轴移动。

## 后续建议

1. 在 2.5D 原型里接入敌人追击、攻击距离和死亡流程。
2. 给墙体、柱子和玩家碰撞补可视化 QA 快照，重点验证柱子前后遮挡与实际碰撞区域一致。
3. 把旧 2D 战斗场景的清怪开门逻辑迁移到 2.5D 原型，但继续保留旧场景作为对照。
4. 在玩家可控后再替换正式 2D billboard 素材，避免美术素材先行时无法判断动线和碰撞问题。

## 注意

- 本轮不修改玩家存档，不清理任何本地存档。
- 本轮仍使用灰盒/可读性标记，未引入代码生成的正式美术素材。
