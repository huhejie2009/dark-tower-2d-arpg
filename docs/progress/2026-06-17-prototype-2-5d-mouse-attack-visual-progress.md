# 2026-06-17 2.5D 原型鼠标指向攻击与攻击弧进度

## 背景

上一轮 2.5D 原型已经支持左键攻击，但攻击方向仍主要依赖移动方向或测试指定方向。试玩时这会造成一个问题：玩家点击敌人时，不一定能直观看到攻击到底打向哪里。本轮继续推进可玩性与可读性，把左键攻击改为优先使用鼠标屏幕位置投射到 3D 战斗平面，并加入临时攻击弧可视化。

## 本轮完成

- 鼠标指向攻击：
  - 左键事件读取鼠标屏幕坐标。
  - Camera3D 将屏幕坐标投射到玩家所在的 XZ 战斗平面。
  - 投射点与玩家位置形成攻击方向。
  - 若测试或后续系统显式指定攻击方向，仍可覆盖鼠标方向。
- 临时攻击弧可视化：
  - 新增 `PlayerAttackArcMarker` 灰盒节点。
  - 攻击时显示半透明扇形区域，表达当前攻击方向和范围。
  - 攻击冷却结束后自动隐藏。
- 测试与快照接口：
  - `get_player_screen_position_for_test()`
  - `get_enemy_screen_position_for_test(index)`
  - `build_player_attack_visual_snapshot_for_test()`
  - 攻击快照新增 `aim_source`，可区分 `mouse`、`override`、`test`、`fallback`。
- 新增回归测试：
  - `tests/regression/regression_prototype_2_5d_mouse_attack_visual_contract.gd`

## 验收标准

- 测试点击敌人的屏幕坐标后，攻击方向必须来自鼠标投射。
- 鼠标指向攻击必须命中前方敌人，并减少敌人存活数量。
- 攻击快照必须记录 `aim_source == "mouse"`。
- 攻击弧节点必须存在，攻击时可见，并朝向本次攻击方向。
- 攻击弧覆盖范围不能小于实际攻击范围。

## 后续建议

1. 将临时攻击弧替换为独立 VFX 管线，不和人物动画混在一起。
2. 为攻击接入正式前摇、命中帧、后摇，让视觉和伤害时机一致。
3. 将玩家攻击动画状态接入 2.5D billboard actor，让角色动作和攻击弧同步。
4. 做一次实机视觉 QA，检查鼠标指向、攻击弧和敌人死亡反馈是否足够清楚。

## 注意

- 本轮不修改玩家存档，不触发真实楼层奖励保存。
- 本轮攻击弧是灰盒可读性标记，不是正式美术素材。
