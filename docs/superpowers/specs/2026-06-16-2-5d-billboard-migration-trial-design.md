# 2026-06-16 2.5D 纸片角色迁移试验设计

## 目标

本试验用于验证《暗塔》是否应该从当前纯 2D 战斗场景，迁移到“3D 空间 + 2D 素材角色”的 2.5D 制作管线。

核心判断标准不是技术炫技，而是解决当前最影响体验的三个问题：

- 场景不像真实空间，墙、柱子、门、遮挡和碰撞都显得抽象。
- 人物和怪物动画制作难度高，纯 2D 斜视角容易让动作、脚底锚点和碰撞体互相打架。
- 美术资产缺少统一承载方式，后续继续堆系统会让游戏越来越像调试界面，而不是一款完整游戏。

试验成功后，游戏仍然以 2D 素材为主要角色表现方式；不是改成 3D 角色游戏。

## 推荐方向

采用 2.5D billboard 方案：

- 场景：使用 Godot 3D 场景承载地面、墙体、柱子、门、坡道、遮挡和碰撞。
- 相机：使用固定正交 Camera3D，形成稳定的俯视/轻微斜视游戏视角。
- 角色：玩家、敌人、NPC、掉落和传送门优先使用 Sprite3D 或等价 2D 贴片。
- 动画：角色动作继续使用 2D 序列帧，按动作和方向独立生产。
- 武器：玩家身体动画不烤入武器，武器继续走独立挂点和独立图层。
- 特效：攻击轨迹、命中特效、神罚预警、掉落光效继续与角色动画分离。

这个方向类似《饥荒》所采用的“二维角色在空间化世界中行动”的制作思路，但《暗塔》的视觉目标仍然是冷峻、荒凉、通天塔内部、深色水泥和暗光条，而不是卡通手绘荒野。

## 不做范围

本试验阶段不做以下内容：

- 不迁移完整主项目。
- 不删除或清空玩家存档。
- 不重做背包、装备、商人、仓库等系统。
- 不切换正式主流程入口。
- 不把现有纯 2D 战斗场景删除。
- 不制作完整 8 方向全套角色资产。
- 不使用代码生成的角色最终素材。
- 不把武器直接画死在玩家身体帧里。

## 试验切片

新增一个独立试验场景，建议命名为：

```text
scenes/prototypes/Prototype2_5DCombatRoom.tscn
```

试验场景只需要承载一个 30 秒内可判断方向是否成立的小切片：

- 一间标准塔内战斗房间。
- 3D 地面网格，低饱和深灰石板材质。
- 3D 墙体和柱子，具备真实碰撞体。
- 一个玩家纸片角色。
- 两个近战敌人纸片角色。
- 一个可拾取掉落物。
- 一个清怪后出现的传送门或出口标记。
- 一个固定正交相机。
- 一个调试 HUD，显示当前试验模式和基础战斗信息。

## 视觉规则

场景应该优先验证“像一款游戏”的整体画面，而不是追求最终美术质量。

视觉原则：

- 房间空间必须一眼可读，地面、墙体、柱子和门的层级清楚。
- 角色必须看得出脚底接触地面，而不是漂浮。
- 角色、敌人、掉落、出口不能被深色背景吞掉。
- 柱子和墙体允许遮挡角色，但不能让玩家误判可通行区域。
- 屏幕截图中应能在 1 秒内识别玩家、敌人、障碍、目标和出口。

推荐临时资产策略：

- 场景可以先使用简单 3D 几何体和低饱和材质。
- 角色可先使用现有 2D 候选素材或占位 Sprite3D。
- 占位素材必须通过 manifest 标记为 trial/placeholder，不能混入正式美术命名。

## 碰撞与遮挡规则

空间逻辑统一放在 3D 的 XZ 平面：

- 玩家移动：XZ 平面移动，Y 轴只用于高度或视觉层级。
- 玩家碰撞：使用 CapsuleShape3D 或 CylinderShape3D。
- 敌人碰撞：使用 CapsuleShape3D 或 CylinderShape3D。
- 柱子碰撞：只以真实柱脚或柱体占地为准，不使用视觉投影面积作为碰撞。
- 墙体碰撞：使用简单 BoxShape3D。
- 拾取判定：以玩家脚底/身体中心到掉落物 XZ 距离为准。
- 攻击判定：先使用 XZ 平面扇形或圆形范围，不依赖画面像素。

遮挡依靠 3D 深度和相机视角验证，减少纯 2D YSort 规则对复杂场景的压力。

## 角色素材规则

角色仍按 2D 素材生产，试验阶段验证以下接口：

```text
actor_render_mode: sprite3d_billboard
animation_pipeline: action_separated
directional_target: 4dir_first
weapon_layer_mode: external_attach
body_sprites_must_exclude_weapon: true
combat_vfx_separated: true
```

第一阶段只要求 4 方向：

- down
- left
- right
- up

每个方向仍按动作独立：

- idle
- run
- attack
- death

验收时重点看：

- 跑步是否有明确换脚。
- 攻击是否有预备、发力、命中、收招。
- 敌人攻击前摇是否清楚。
- 死亡是否有身体倒下或瓦解过程。
- 武器能否作为独立层挂接，不破坏身体动画。

## 技术接口

试验阶段建议新增独立适配层，而不是直接改写当前 `Game2D.gd`：

- `Prototype2_5DCombatRoom.gd`：试验场景主控。
- `BillboardActor3D.gd`：2D 角色在 3D 空间中的显示和朝向适配。
- `BillboardActorAnimationProfile.gd`：动作、方向、帧率、锚点和 Sprite3D 资源配置。
- `CombatPlane3DService.gd`：XZ 平面距离、攻击范围、拾取范围等计算。
- `Prototype2_5DVisualQaService.gd`：截图验收所需的节点和状态快照。

这些接口只服务试验切片，验证通过后再决定是否把正式战斗场景迁移。

## 验收标准

试验通过必须同时满足以下条件：

- Headless 场景启动测试通过，退出码为 0。
- 实机截图中，房间空间、玩家、敌人、柱子、墙体和出口清晰可读。
- 玩家无法穿过墙体和柱子碰撞体。
- 玩家可以贴近柱子前方移动，而不会被柱子的视觉高度错误阻挡。
- 玩家从柱子后方经过时，遮挡关系看起来合理。
- 两个敌人可以在 XZ 平面追击玩家。
- 敌人攻击范围以空间距离判定，不依赖贴图晃动。
- 清怪后能够显示出口或试验完成标记。
- 当前正式 2D 主流程不受影响。
- 不清空、不覆盖、不迁移玩家存档。

## 失败标准

如果出现以下任一情况，应停止迁移方向，仅保留试验记录：

- 角色纸片感过强，截图比当前 2D 方案更割裂。
- 4 方向素材在固定相机下明显不够用，必须立即投入 8 方向才可接受。
- 3D 碰撞和 2D 动画适配成本明显高于继续优化纯 2D。
- Godot 4.6.2 中 Sprite3D/动画/透明排序导致大量不可控遮挡问题。
- 试验切片无法在不破坏当前主流程的情况下独立运行。

## 推荐实施顺序

1. 新增独立 2.5D 原型场景，不接入主菜单。
2. 搭建灰盒房间：地面、墙体、柱子、门。
3. 添加固定正交 Camera3D。
4. 添加玩家 Sprite3D 纸片角色和 XZ 平面移动。
5. 添加柱子/墙体碰撞验证。
6. 添加两个敌人追击和攻击范围验证。
7. 添加掉落和清怪出口。
8. 添加截图 QA 和回归测试。
9. 写一份视觉对比进度记录，决定是否进入正式迁移计划。

## 决策门

本试验完成后只做一个决策：

```text
继续 2.5D 迁移 / 回到纯 2D 优化 / 保留 2.5D 只用于特殊场景
```

在这个决策完成前，不应该把背包、装备、主城、楼层循环等正式系统迁到 3D 场景中。
